# 内置演练页 + 交互录制器

一个自包含的演练页面（表单、标签页、每次打开都会重建 DOM 的弹窗、可滚动列表、
延迟异步回写），以及**只在该演练页工作**的交互录制器：录制真实操作、逐步保存
执行前条件与执行后状态摘要、从初始状态逐步回放，并在第一处分歧处停住。

## 运行

页面是纯静态文件，直接用浏览器打开即可（无需构建）：

```bash
# 任选其一
open public/index.html
npx serve public
```

右下角为录制器面板：**开始新录制 / 停止 / 回放最新**。

测试（Node ≥ 18，使用内置 `node:test` + jsdom）：

```bash
npm install
npm test
```

## 目录

```
public/
  index.html    演练页：标签页、表单（含密码）、偏好、滚动日志、可重建弹窗
  app.js        页面行为；暴露 window.WalkthroughApp.reset() 作为“初始状态”
  recorder.js   录制器（录制 / 持久化 / 回放 / 分歧定位 / 面板）
  styles.css
test/           24 个测试（jsdom 驱动真实 DOM 与真实事件）
```

## 录制器语义

**页面守卫。** 录制器只在带 `data-walkthrough-page` 标记的页面挂载
（`public/index.html` 的根节点）。其它页面不绑定事件、不注入面板、
`startRecording()` 返回 `null`。

**录制动作与目标。** 在捕获阶段监听 `click / input / focus(in) / scroll`：

- 所有目标一律使用稳定元素 ID（`getElementById` 回放）；窗口滚动使用 `__window__`。
- 同一文本字段的连续按键合并为一步（最终值入库）；连续滚动合并为一步（最终位置入库）。
- 点击可聚焦控件时，其焦点变化并入同一步，回放时同步聚焦。
- 录制器自身面板在演练根节点之外，点击面板永远不会入轨迹。

**每步保存的数据**（`track.steps[i]`）：

| 字段 | 含义 |
| --- | --- |
| `type` / `target` | 动作类型与稳定 ID |
| `pre` | 执行前条件：焦点、标签页、弹窗开关与版本、全部字段值、文本节点、动态条目列表、滚动位置 |
| `post` | 执行后可观察状态摘要（按该步的沉淀时长采集） |
| `settleMs` | 该步实际经过的沉淀时长，回放时镜像同一时间线（吸收异步回写） |
| `value` / `redacted` | 输入结果；密码步恒为 `value:null, redacted:true` |

**动态条目列表。** 带 `data-snapshot-list` 的容器（活动日志的 `<ul id="wt-log-list">`）
会按条目顺序采集为 `snap.lists[id]` 文本数组。于是“追加日志”这类操作的两类
可见变化都成为可核对的分歧：条目**新增/删除**体现为数组长度差异（如
`lists.wt-log-list[21]` 录制时缺失、当前多出一条），某条**文本改动**体现为
该下标处的值差异；`firstDiff` 停在第一处不一致的条目。

**非稳定文本归一化。** 所有采集文本（`data-snapshot-text` 与列表条目）都先经过
`normalizeText`：当前时间/日期写法（`14:03:07`、`9:05 AM`、`2026-10-03`、
`2026-10-03T14:03:07.000Z` 等）统一替换为 `<时间>` / `<日期>` 占位符。
因此录制与回放之间真实墙钟时间不同**不会**制造伪分歧；但条目序号、业务文字
（“手动追加”vs“系统自动生成”）原样保留，真实内容差异仍会被抓到。

**密码脱敏。** 密码字段在 `pre`、`post`、步骤体和持久化数据中只出现
`{ "type": "password", "changed": true|false }`，不接触、不保存任何字符。
回放时仅把字段推进“已改变”状态（瞬时占位符不入库）。

**回放（从初始状态逐步执行）。** 每次回放先调用 `WalkthroughApp.reset()` 复位，
并先核对轨迹的 `initialState`，随后对每一步严格按序：

1. **目标缺失** → 停在该步（`phase:"missing"`，当前值展示为 `null`）；
2. **执行前条件不符**（`pre` 与当前状态的第一处分歧）→ 停在该步；
3. 执行动作，等待与录制时相同的沉淀时间（迟到的异步回写在此窗口落地）；
4. **执行后状态分歧**（`post` 与当前状态的第一处分歧）→ 停在该步。

任何一种停驻都会立即终止：后续步骤**不会执行**，不会产生“看似成功”的后续状态。
面板与 `recorder.halt` 同时给出：第几步、动作类型与目标、分歧字段路径
（如 `values.wt-role-user.checked`）、**录制值**与**当前值**。

**迟到异步与会话令牌。** 每次“开始新录制”或“停止回放”都会递增 `session`
并取消挂起定时器；所有延迟回调都捕获自己的令牌，令牌失效后直接丢弃，
因此停止录制后才落地的异步界面更新（示例页弹窗确认后 30ms 的状态回写）
不可能再写进旧轨迹，也不可能改动已定稿步骤。回放期间轨迹只读，迟到更新
同样不可能污染轨迹或回放循环。此外，**停在分歧处（或手动停止回放）时**，
录制器还会作废演练页登记的挂起定时器（`WalkthroughApp.pendingAsync`），
冻结停驻现场——用户对照“录制值/当前值”时，页面不会被随后落地的回写改动，
停驻报告也保持定稿时的快照。

**跨刷新保存。** 每步定稿即写入 `localStorage`
（键 `walkthrough-recorder:tracks:v1`），刷新/重开页面后轨迹仍在，
可直接回放最新轨迹。

## 测试覆盖（24）

- **动态日志分歧**：追加后条目数量变化 → 停在多出的第一条（`lists.wt-log-list[21]`）；
  数量相同但业务文本变化 → 停在改动下标；初始条目数变化 → `initial` 分歧一步不执行；
  仅当前时间不同 → 归一化后回放成功；`normalizeText` 单元覆盖；
- **弹窗重建**：两次打开产生全新 DOM 节点但 ID 稳定，完整回放一致，异步回写被正确吸收；
- **输入脱敏**：轨迹与持久化中无密码片段，只出现 `changed` 布尔位，且可回放；
- **目标变化**：目标被删除 → `missing` 停驻；节点被替换但 ID 不变 → 成功；
  同 ID 行为变化 → `post` 分歧停驻；
- **首次分歧定位**：初始状态、中途 `pre`、`post` 三类停驻，录制值/当前值齐备，
  后续步骤确定未执行；`firstDiff` 单元测试（字典序首路径、数组、缺失键）；
- **迟到异步**：停止录制 / 开始新录制 / 停止回放 / 回放停在分歧处四种场景，
  迟到更新不入旧轨迹、不改动停驻页面与报告；
- **跨刷新**：共享持久化的第二次页面会话可读到并回放轨迹；
- 另含 focus/select/checkbox/radio/scroll 完整往返、空闲不录制、面板停驻 UI、页面守卫。

> 测试用固定 `sleep` 对齐录制器 60ms 沉淀窗口，在并行高负载下容易抢跑，
> 故 `npm test` 以 `--test-concurrency=1` 串行执行各测试文件。
